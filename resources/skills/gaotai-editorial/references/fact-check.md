# 事实核查清单

一篇稿子因为一个编造的数字被骂，比因为观点不够锐利被骂得多得多。
观点可以吵，数据不能编。这份清单是发布前的最后一道闸。

## 适用场景

- 稿子里引用了数字、日期、人物、机构、政策或引语。
- 稿子由 AI 参与生成（AI 编数字的概率显著高于人）。
- 要把稿子推到外部渠道之前。

## 必查清单

**数字**
- [ ] 每个数字有出处吗？来源能被别人找到吗？
- [ ] 口径写清了吗？（同比还是环比、哪个季度、含不含某项业务、样本量多少）
- [ ] 单位对吗？（万 / 亿、百分比 / 百分点、时 / 分）
- [ ] 这个数字是不是从别处抄来时变了形？（增速、数量级最容易出错）
- [ ] 换算过没有？（人民币、美元；小时、分钟）

**时间**
- [ ] 日期写全了吗？（只有「去年」不够，要具体到月或日）
- [ ] 时区/版本号对吗？（「v2.3 之后」要写清是哪个版本）

**人与机构**
- [ ] 头衔准确吗？（「联合创始人」还是「创始人」）
- [ ] 引语是原话吗？引语是转述的要标明是转述。
- [ ] 机构名是全称吗？

**引语与出处**
- [ ] 引用了别人的结论，写明出处了吗？
- [ ] 图表/截图是自制的还是转载的？转载的注明来源。

**因果**
- [ ] 「因为」真的成立吗？相关不等于因果。
- [ ] 有没有把个案当趋势？

**自造内容**
- [ ] 这句话是我写的还是模型写的？模型给的具体数字**一律**要核。
- [ ] 「某业内人士」有没有真实来源？没有就删掉这个说法。

## 核查方法

1. **回溯**：每一个数字追问一句「这个数从哪来的」。
   追不到出处的，删掉或改成「约」「据估算」，不要留着装作确定。
2. **量级检查**：把数字放回常识里对一遍。
   「服务了 3 亿用户」的公司名单对不上，说明这个数字有问题。
3. **交叉验证**：能查到的，至少用两个来源对一遍。
   只有单一来源且无法验证的，标注为「单一来源」。
4. **代词测试**：把稿子里的「数据显示」换成具体来源，
   换不动的句子都是伪证据。

## 处理原则

| 情况 | 怎么办 |
| --- | --- |
| 查到了 | 写明确切数字与口径 |
| 查到了但口径不同 | 写你的口径，并说明与流传版本不同 |
| 没查到 | 改成「据 X 透露」需有出处；否则删掉该数字 |
| 数字是模型给的 | 一律核；核不到就删 |

**永远不要做的事**：把不确定的数字写得更确定。
「大约 30%」写成「30%」，是最低成本的造假。

## 常见毛病

- **数字很精确但没来源**：「73.4% 的开发者……」——精确度本身就是伪装。
- **把引用当证据**：「某专家表示」不是证据。
- **通篇只有一个来源**且不可查。
- **图表与正文数字不一致**——图表是手画的，正文改了图表没改。
- **旧数据当新数据**：文章发在明年，数据是去年的。
