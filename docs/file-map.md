# 项目文件清单 · 接手指南

> 这份是给**第一次接触这个项目的人**看的：每个文件归谁管、改它要注意什么、怎么跑起来、哪里有坑。
> 产品口径看 [`spec.md`](spec.md)（权威），架构判断看 [`architecture-review.md`](architecture-review.md)。

---

## 0. 这是什么

**稿台**：一个**本地**跑的公众号写作工作台。桌面客户端（Electron + Next.js），
数据、密钥都在使用者自己的机器上，没有服务器、没有账号、没有按量计费。

一条主线：**把素材交给 AI，它分四道工序（材料解读 → 选题 → 大纲 → 正文）一步步变成能发出去的稿子**，
每道工序都要人签字才往下走。

---

## 1. 三条命令跑起来

```bash
npm install                # 装依赖（better-sqlite3 与 canvas 都是预编译二进制）
npm run dev                # 开发态：http://127.0.0.1:3060
npm test                   # 全部单测（366 条，不需要模型、不联网）
```

出包（Windows）：

```bash
npm run desktop:build      # 产物在 release/：安装包 + 免安装版
```

> 出包会**覆盖** `release/` 里的文件。已经在跑的免安装版会被文件锁住，
> 出包前先关掉它。

## 2. 目录地图

```
src/app/          页面与 API 路由（Next.js App Router）
src/lib/          领域逻辑：接口封装、编排、数据访问
src/tests/        单测（自带极简 runner，不引测试框架）
electron/         桌面壳：窗口、菜单、驱动后端子进程
resources/        只读资源，随安装包分发（提示词/专题/技能包/排版样式包）
scripts/          构建与资源组装脚本
docs/             规格与说明
```

### 2.1 桌面壳（`electron/`）

| 文件 | 作用 | 要注意的 |
| --- | --- | --- |
| `main.js` | 起后端子进程、开窗口、注入会话 cookie | **启动令牌**逻辑在这里（每次启动随机生成，只在进程内存里）；端口是挑空闲的，不是固定的 |
| `preload.js` | 给渲染进程暴露「读本机口令」的能力 | 别把别的能力顺手暴露出去 |

### 2.2 页面与接口（`src/app/`）

| 路径 | 作用 |
| --- | --- |
| `page.tsx` | 工作台（开新稿、看最近的稿子） |
| `projects/[id]/editor.tsx` | **稿件页**，四道工序的主工作区：工序带 + 对话 + 产出 + 技能包勾选 + 插入图片 |
| `files/` | 素材库：上传图片、复制引用、删除 |
| `wechat/` | 公众号面板：配置、预览、推草稿箱 |
| `layout/` | 排版模板：导入样式包 → 取舍 → 编辑 → 预览 |
| `agent-config/` | 模型配置（Base URL / Key / 模型名），密钥加密后落盘 |
| `api/…` | REST 接口，**全部需要登录**（见 §4） |

### 2.3 领域逻辑（`src/lib/`）

| 文件 | 作用 | 要注意的 |
| --- | --- | --- |
| `stage-engine.ts` | **工序编排**：拼提示词、调模型、落库 | 正文阶段**不给模型任何工具**；写作方法由服务端注入（`methodGuidance`） |
| `llm.ts` | OpenAI 兼容端点客户端 | 不引任何 Agent 框架 |
| `markdown.ts` | Markdown → 公众号 HTML（走排版部件模板） | 公众号正文**不产出可点击链接** |
| `layout-template.ts` | 排版模板模型：部件、清洗、解析 | 清洗器对占位符、标签名、属性白名单都很敏感，改动前先读测试 |
| `layout-store.ts` | 模板存取 + 「这篇用哪套模板」的优先级 | |
| `files.ts` | 素材库：存图、读图、地址编码、文件名清洗 | 地址按段百分号编码；**推草稿时要解码回文件名**才找得到文件 |
| `wechat.ts` / `wechat-images.ts` | 微信接口 + 正文图 CDN 化 | 公众号不认外链图，正文里的本机地址必须逐张换成微信地址 |
| `wechat-check.ts` | 通道检查 + 错误码翻人话 | 40164 会直接把该填的 IP 报出来 |
| `db.ts` / `repo.ts` | SQLite schema / 数据访问 | **SQL 只在 `repo.ts` 里** |
| `paths.ts` | 路径契约：只读资源 / 可写数据分离 | 打包态靠 `GAOTAI_RESOURCE_DIR` / `GAOTAI_DATA_DIR` 两个环境变量 |
| `auth.ts` | 口令与会话 | 桌面端靠启动令牌自动换会话，用户看不到登录页 |
| `skills.ts` | 技能包访问层 | 路径安全校验、只读、只能读本次启用的技能 |

### 2.4 随包资源（`resources/`）

| 目录 | 内容 | 谁能改 |
| --- | --- | --- |
| `prompts/` | 七份阶段提示词（system / brief / angle / outline / article / style-profile / image-prompt） | **用户可以直接改，改完重启生效**（提示词是进程内缓存的） |
| `topics/<id>/` | 公开专题：`meta.yaml`（元信息 + 默认技能）+ `rules.md`（写作规则正文） | 同上 |
| `skills/<技能名>/` | 写作技能包：`SKILL.md`（YAML 头 + 方法）+ `references/` | 同上；`name` 必须等于目录名 |
| `layout-packs/` | 21 套随包排版样式包（rico-md 的 MIT 部分翻译）+ LICENSE/SOURCE 溯源 | 改样式包要同步 `SOURCE.json` |

### 2.5 脚本（`scripts/`）

| 脚本 | 作用 |
| --- | --- |
| `prepare-resources.mjs` | 把 `resources/` 组装成 `dist/app-resources`（打包时用） |
| `copy-standalone-assets.mjs` / `sanitize-standalone.mjs` | 修 Next standalone 产物（静态资源、路径） |
| `ensure-runtime-deps.mjs` | 确认 standalone 里的原生依赖齐全 |
| `run-desktop.mjs` | 开发态起桌面客户端 |

## 3. 数据与密钥在哪

| 东西 | 位置 | 说明 |
| --- | --- | --- |
| 源码里的 `.env` | 项目根 | **只有本地开发用**，已 gitignore；归档里不含它 |
| 桌面版真正的 `.env` | `%APPDATA%\gaotai\.env` | 首次运行自动生成：随机登录口令 + 会话密钥 + 你在界面里填的模型 Key / 公众号凭据 |
| 数据库 | `%APPDATA%\gaotai\data\gaotai.sqlite` | 稿件、阶段产出、风格画像 |
| 配图 | `%APPDATA%\gaotai\images\` | 素材库里的图 |
| 日志 | `%APPDATA%\gaotai\backend.log`、`startup-error.log` | 桌面版没有终端，出问题时这两个文件是唯一线索 |

**开发态**里数据落在项目根的 `data/`（已 gitignore）。

## 4. 登录是怎么没感的

- 桌面客户端**每次启动**随机生成一个「启动令牌」，只通过环境变量交给后端，**不落盘**；
  窗口打开前用它换一个会话（`POST /api/auth/session`）。
- 所以用户**永远看不到登录页**，30 天会话过期也对用户不可见（每次启动自动续）。
- 只有**浏览器直接访问 `127.0.0.1`** 那一路需要本机口令 —— 因为任何本地网页都够得着这个端口，
  没有会话的话，恶意网页能让你的浏览器替它调你的接口（烧额度、推公众号草稿箱）。

改动这块时注意：口令是**机器内部凭证**，不是用户凭证。别把它做成用户要填的东西。

## 6. 坑（接手的人一定会踩）

1. **提示词是进程内缓存的**：改完 `resources/prompts/*.md` **要重启**才生效。
   `clearPromptCache()` 有导出但没人调用——别以为调了它就生效。
2. **正文阶段不要给模型工具**。给 `check_prose` 或 `read_skill_file` 都是「程序型指令」，
   真模型实测会把思考额度吃光、正文一个字没有。写作方法由服务端注入。
3. **注入方法节，不要注入禁令清单**。十条硬禁令会让模型逐条核对，
   实测 16384 额度全进了思考、正文 0 字。方法给出路，禁令只给墙。
4. **正文阶段不给字数指令**。`renderLengthInstruction()` 的参数类型里根本没有 `article`——
   不是「正文分支返回空」，是根本传不进来。
5. **正文里的图片地址是百分号编码的**（文件名带中文）。推草稿时必须**解码**回文件名
   才找得到磁盘上的文件；不解码 → 图不上传微信 → 稿子推出去图是空的。
6. **公众号不认外链图**。导入的现成文章里带外链图的，必须先下载到本机再上传。
7. **改 `layout-template.ts` 的清洗器前先跑测试**：样式值里的 `{{变量}}` 占位符
   曾经被连同整条声明一起丢掉 → 部件**悄悄没了样式**而且不报错。
8. **打包前关掉正在运行的免安装版**，否则文件被锁，portable 目标会一直等。
9. **出包会在 `%TEMP%` 留下 `ns*.tmp`**（NSIS 编译临时目录），收尾时清掉。
10. **Windows 上 Node 调 cmd.exe**：命令串不要额外包外层引号，要开 `windowsVerbatimArguments`；
    否则 cmd 会把整条命令当成**程序名**去找，报「不是内部或外部命令」。
