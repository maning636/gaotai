## 3. 建私有库并推送（已完成 2026-10-26；以下为实际路径 + 换机复现）

> **实际发生了什么**：本机没装 `gh`，SSH key 也没注册到 GitHub（见 §2.1），所以走的是
> **Windows 凭据管理器里的 GitHub 令牌 → GitHub API 建私有库 → HTTPS push**。
> 本节保留完整步骤，换机或重建仓库时照做即可。

### 3.1 建私有库（实际：凭据管理器令牌调 GitHub API）

本机 `credential.helper=manager`（系统级）里存着 GitHub 令牌，直接用它调 API，
不用装 `gh`，也不用把令牌写进命令行历史：

```powershell
# 从凭据管理器取 GitHub 账号的令牌（会提示确认，令牌只在这个进程里）
"protocol=https`nhost=github.com`n" | git credential fill

# 用取到的 password 建私有库（令牌放 Authorization 头，不落盘）
$token = '<上一步输出的 password>'
Invoke-RestMethod -Method Post -Uri https://api.github.com/user/repos `
  -Headers @{ Authorization = "Bearer $token"; 'User-Agent' = 'gaotai' } `
  -Body (@{ name = 'gaotai'; private = $true } | ConvertTo-Json)
```

建完确认三点：Visibility = Private、没有勾任何初始化文件（README / .gitignore / license）、
默认分支随后改成 `main`。

### 3.3 push 挂死怎么办（**必读**，方法保留）

本机全局配了 `http.proxy=http://127.0.0.1:7897`。**代理通不通每次都不一样**
（实测过翻转：一次代理死直连活，一次反过来）。**当前实测（2026-10-26）：直连与代理都通**，
push 没有挂死；但换网络环境后这套探测仍然适用。

先探两条路，哪条通用哪条：

```powershell
# 探直连
git -c http.proxy= -c https.proxy= ls-remote origin
# 探代理
git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 ls-remote origin
```

- 哪条 2 秒内返回就用哪条推（`git push` 同样带这两个 `-c`）。
- **只对当次命令加 `-c`**，别改全局配置（改了会影响别的项目）。
- SSH 不读 `http.proxy`，本可以绕开代理——但本机 key 未注册 GitHub，**这条路不通**，别试。

## 4. 本机开发与出包

```powershell
npm install          # 依赖
npm run dev          # 开发态 http://127.0.0.1:3060
npm run lint         # ESLint（未使用变量/导入、明显错误）
npm run typecheck    # tsc --noEmit
npm test             # 373 条单测，不需要模型、不联网
npm run deps-gate    # 依赖声明闸门（引用与声明双向对齐）
npm run verify       # 以上四道本地全跑一遍（CI 同款）
npm run desktop:build   # → release/（安装包 + 免安装版）
```

出包注意事项：

1. **先关掉正在运行的 `稿台.exe`**，否则 portable 目标会一直等文件锁（表现是构建卡在「building target=portable … waiting for unlock」）。
2. 出包会在 `%TEMP%` 留下 `ns*.tmp`（NSIS 编译临时目录），收尾清掉。
3. **没有 Visual Studio 的机器**：`npm install` 要加 `--ignore-scripts`，然后手动跑 `node scripts/ensure-runtime-deps.mjs` 补原生模块。
4. 别在 `release/` 目录里双击安装包测东西 —— 每次出包都会覆盖那个文件，正在开的安装向导会反复弹。
5. **electron-builder 下载二进制不走系统代理**（实测 2026-10-26）：直连 GitHub 超时时，打包会在最后一步卡死，报 `Timeout awaiting 'request' for 600000ms`（前五步全正常，只有 electron-builder 挂）。给命令加环境变量即可：
   ```bash
   HTTPS_PROXY=http://127.0.0.1:7897 HTTP_PROXY=http://127.0.0.1:7897 npm run desktop:build
   # 或走镜像（代理也不通时）
   ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/ npm run desktop:build
   ```

**免费 + 私域分发**，没有服务器、没有按量计费：

```

```

> 分发形态的决策记录见

> 不出 GitHub Release，正式产物只在本地 `npm run desktop:build` 出；CI 打包只做手动烟测（软门）。

| 形态 | 文件 | 建议 |
| --- | --- | --- |

| 安装包 | `release\Gaotai-Setup-0.1.0.exe` | 需要固定安装位置的用户 |

用户侧的体验（这些是设计承诺，交付时别改坏）：

- **首次打开直接进**，没有账号、没有注册、没有激活码（桌面端用启动令牌自动换会话）
- **模型要自己带 Key**：在「模型」页填 Base URL / Key / 模型名，稿台不自带模型、不按字收费
- **数据全在用户机器上**：`%APPDATA%\gaotai`
- 未签名 → SmartScreen 会说「未知发布者」，点「更多信息 → 仍要运行」→ **推广文案里要提前说**
- 推公众号草稿要过 **IP 白名单**（微信只认最多 20 个精确公网 IPv4）——这是唯一绕不过去的坎，推广时别承诺"装完就能推"

## 7. 会踩的坑

完整 10 条在 [`file-map.md`](file-map.md) 的 §6，这里是最容易致命的几条：

1. **提示词是进程内缓存的**：改 `resources/prompts/*.md` **必须重启**才生效。
2. **正文阶段不要给模型工具**：给 `check_prose` / `read_skill_file` 会把思考额度吃光，正文一个字交不出来（真模型实测）。写作方法由服务端注入。
3. **注入方法，不要注入禁令清单**：十条硬禁令会让模型逐条核对，实测 16384 额度全进思考、正文 0 字。
4. **正文不给字数指令**：`renderLengthInstruction()` 的参数类型里根本没有 `article`。
5. **正文里的图片地址是百分号编码的**：推草稿时必须解码回文件名才找得到文件，否则图不会上传微信、稿子推出去是空的。
6. **公众号不认外链图**：导入的老文章带外链图，要先下载到本机再上传。
7. **改 `layout-template.ts` 的清洗器前先跑测试**：样式值里的 `{{变量}}` 曾被连同整条声明丢掉 → 部件悄悄没样式且不报错。
8. **出包前关掉运行中的实例**；出包后清 `%TEMP%\ns*.tmp`。
9. **Windows 上 Node 调 cmd.exe**：命令串不要额外包外层引号，要开 `windowsVerbatimArguments`。
10. **git push 挂死先探直连/代理**（§3.3），别原地重试。
