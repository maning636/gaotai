# ADR-0002：正文阶段不给模型工具、不注入禁令清单、不下字数指令

日期：2026-10-26 ｜ 状态：已采纳 ｜ 决策者：maning636
证据档：已验证（真模型实测，2026-10-23，详见 docs/file-map.md §5-§6）

## 背景

正文（第四道工序）是唯一「要产出大量字」的阶段。早期版本给正文模型
配了与其他工序相同的工具（`check_prose` / `read_skill_file`）与十条
硬禁令清单，并按传统习惯下字数指令。

## 决策

正文阶段的模型请求满足三条：

1. **不给工具**：写作方法由服务端注入提示词，模型不需要调工具查。
2. **不注入禁令清单**：注入「要做什么」（方法），不注入「不许做什么」
   （十条禁令）。
3. **不下字数指令**：`renderLengthInstruction()` 不接受 `article` 类型；
   字数目标只管到选题与大纲两道工序。

## 证据（真模型实测，2026-10-23）

- 给工具：16384 token 额度全部进思考，正文 0 字。
- 注入十条禁令：模型逐条核对合规性，16384 额度全进思考，正文 0 字。
- 字数指令：正文阶段追字数会让模型放弃结构去凑数，产出质量下降。

## 否掉了什么

- 「工具是通用能力，所有阶段都给」——对思考型模型，正文阶段工具是
  纯粹的注意力税。
- 「禁令越全越安全」——禁令清单诱发逐条自查行为，反而杀死产出。
- 「字数是质量指标」——对 700-1200 字的公众号文体，结构完整比凑数重要。

## 代价

- 写作方法必须提前写进提示词，提示词维护成本高（7 份阶段提示词，
  改完需重启进程生效——进程内缓存）。
- 用户想要超长文（如 3000 字深度稿）时无字数手段，只能靠大纲分段
  间接控制。

## 实现

- 工具注入控制：`src/lib/llm.ts`（`parseTextToolCalls` 与请求组装）；
  字数：`src/lib/length-target.ts`；分节生成：`src/lib/section-writer.ts`。
