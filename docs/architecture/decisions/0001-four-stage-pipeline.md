# ADR-0001：写作流程采用四道工序流水线，且产出必须逐级签字

日期：2026-10-26 ｜ 状态：已采纳 ｜ 决策者：maning636

## 背景

公众号稿件的生成如果一步到位（素材进、文章出），中间结论无法干预：
模型在草稿阶段虚构的「事实」会被后续阶段当成既定素材继续放大，用户
发现时全篇已歪，只能整篇重写。

## 决策

流程拆为四道工序，每道有明确产出与闸门：

| 工序 | 产出 | 闸门 |
| --- | --- | --- |
| 材料解读 | 硬事实 / 判断 / 待核实 / 缺口 / 角度 | 用户签字 |
| 选题与方向 | 3 个可选角度 | 用户选定 |
| 写作大纲 | 主张 + 推进线 + 分段 | 用户签字 |
| 文章正文 | 完整 Markdown | 定稿 |

**没签字的产出不会被当成定稿往下传**——这是全产品最重要的一条规则。

## 否掉了什么

- **一步生成**：不可干预，草稿错误全篇放大（见上）。
- **自由对话式**（用户随时插话引导方向）：会话状态不可控，「签字」失去
  含义，无法界定哪份产出是定稿。

## 代价

- 流程重：短稿用户要过四次闸门。接受，因为目标用户是公众号创作者，
  一篇稿子的发布成本远高于四次点击。
- 状态机实现复杂度高：`src/lib/stage-engine.ts` 与各阶段上下文
  （`stage-context.ts`）承载了这套约束。

## 实现

- 工序定义：`src/lib/stages.ts`；引擎：`src/lib/stage-engine.ts`。
- 相关测试：`src/tests/stage-engine.test.ts` 等。
