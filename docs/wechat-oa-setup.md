# 稿台 · 服务号对接操作手册

这份手册写给作者本人：手上已经有一个**已认证的微信服务号**，要自己动手把「关注服务号 → 领注册码」这条链路配通。

读者默认没怎么碰过微信后台，所以每一步都写到了「在哪个后台 → 哪个菜单 → 点哪个按钮 → 填什么」。
菜单全路径用引用块标出，方便你照着点。

> 阅读顺序：先把「§0 这条要显眼」看明白，再按 §1–§7 顺序操作，最后用 §8 的清单把要交给我（开发方）
> 的东西收齐。所有菜单名以你当前登录的公众号后台实际显示为准——微信会不定期改版，路径偶尔挪动，
> 看到名字对不上时以实际为准。

---

## 0. 这条要显眼：为什么是服务号，不是小程序

> **小程序没有「关注」关系，也不能主动群发消息。**
> 用户的留存（关注）和每月的主动触达（群发），**只能靠服务号**。
> 小程序在本方案里只承担「领码页 / 查激活状态 / 可选激励视频」这类即用即走的页面，
> 不承担留存和触达。

换句话说：

| 能力 | 服务号 | 小程序 |
| --- | --- | --- |
| 用户「关注」后建立长期关系 | ✅ 有 | ❌ 没有「关注」 |
| 主动推消息到用户（每月 4 次群发） | ✅ 可以 | ❌ 不能主动群发 |
| 被关注后自动回复（带领码链接） | ✅ 可以 | — |
| 关键词回复（如回复「领码」自动给链接） | ✅ 可以 | — |
| 模板消息 / 订阅通知（一次性、需用户授权） | ✅ 可以 | ✅ 也有订阅消息，但需用户每次授权 |
| 长期留存与触达 | ✅ 主力 | ❌ 不行 |

所以本方案的留存闭环是：**服务号负责关注 + 自动回复领码链接 + 每月群发召回；小程序/网页只负责领码表单与状态查询。**
如果你只有订阅号，订阅号也能群发，但**网页授权（OAuth 拿 openid）需要服务号**，所以领码链路里「免输联系方式、直接拿 openid」这一步需要服务号。

## 1. 登录后台与基本前提

1. 浏览器打开 `https://mp.weixin.qq.com/`，用管理员微信扫码登录。
2. 确认左下角/顶部显示的是**服务号**（不是订阅号、不是小程序）。判断方法：
   - 服务号在「设置与开发 → 公众号设置 → 账号详情」里，**帐号类型**显示「服务号」。
   - 服务号每月可群发 **4 次**；订阅号每天 1 次但无网页授权能力。
3. 确认**主体已认证**。未认证的服务号拿不到 AppSecret、配不了自定义菜单跳转网页、也用不了网页授权。
   - 查看位置：`设置与开发 → 公众号设置 → 主体信息`，状态应为「已认证」。

> 如果帐号类型不是服务号，或未认证，先解决这两点再往下做；下面所有步骤都依赖这两条。

## 2. 获取 AppID 与 AppSecret（只存服务器 `.env`）

AppID 是公众号的唯一标识，AppSecret 是调接口的密钥。授权服务器（`license-server`）用它来：
- 验证用户是否真的关注了本服务号；
- 通过网页授权拿用户的 openid（领码页免输联系方式）。

### 2.1 找到 AppID

> 「设置与开发 → 基本配置」

- 页面上方「开发者ID」一栏的 **AppID(开发者ID)**，形如 `wx1234567890abcdef`。复制下来。

### 2.2 找到 / 重置 AppSecret

> 同一页：「设置与开发 → 基本配置 → 开发者密钥(AppSecret)」

- 如果之前没生成过，点「重置」生成；生成时微信会要求**管理员扫码确认**，之后只在页面显示**一次**完整密钥。
- 务必当场复制保存。页面关掉后就再也看不到完整值，只能再「重置」（重置后旧密钥立即失效）。
- 如果不确定之前是否泄露过，建议直接「重置」一次，用新值。

### 2.3 安全提示（重要）

- AppSecret **只放进授权服务器的 `.env`**（例如 `license-server/.env` 的 `WECHAT_APP_SECRET=...`）。
- **绝不**进客户端安装包、**绝不**进 git 仓库。`.env` 必须在 `.gitignore` 里。
- 服务器上文件权限设为 `0600`，只给运行账号可读。
- 后台「基本配置」页面可随时查看 AppID，但 AppSecret 只能重置、不能查看，所以**保存好第一次的值**，丢了就重置。

> 「以当前后台实际菜单为准」：微信偶尔把「基本配置」挪到「设置与开发」或「开发 → 接口设置」下，
> 名称基本不变，找不到时在左侧菜单里搜「基本配置」或「AppID」。

## 3. 服务器 IP 白名单

授权服务器调微信接口（网页授权换 openid、查关注状态、发消息）时，微信只认白名单里的 IP。
不在白名单里的 IP 调接口会返回 `40164` 错误。

> 「设置与开发 → 基本配置 → IP 白名单」

1. 点「修改」（可能要管理员扫码）。
2. 填入服务器**出口公网 IP**。
   - 本项目出网 IP 已知是 `182.200.134.218`，**但请以服务器实际出口 IP 为准**：
     在服务器上执行 `curl -s https://ifconfig.me` 或 `curl -s https://ipinfo.io/ip` 确认。
     家宽/办公室宽带可能是动态 IP，填了之后 IP 一变就会失效，**强烈建议用固定公网 IP 的云服务器**。
3. 保存。

> **改完等 5–10 分钟生效**，不是立即生效。配完立刻测接口仍报 `40164` 是正常的，等几分钟再试。
> 白名单最多可填若干个（以页面提示的数量为准），多个 IP 用回车或逗号分隔（以页面提示为准）。

注意区分两种 IP 白名单，别填错地方：
- **基本配置 → IP 白名单**（本步）：限制**你的服务器**调微信 API 的来源 IP。← 领码链路要用这个。
- **公众号设置 → 功能设置 → 安全域名相关**：网页授权域名，见 §4，限制的是**用户浏览器**访问的域名，不是服务器 IP。

## 4. 网页授权域名与 JS 接口安全域名

领码页 `GET /redeem`（见授权协议 §6.2）需要一个域名，用户通过服务号菜单点进来时，微信会校验该域名是否已在后台登记。

### 4.1 网页授权域名（拿 openid 必需）

> 「设置与开发 → 公众号设置 → 功能设置 → 网页授权域名」

- 点「设置」，填你的**授权域名**（不带 `http://`、不带路径）：`license.maning789link.top`。
- 微信要求在该域名根目录放一个校验文件（如 `MP_xxx.txt`），下载它并上传到你 Web 服务器的对应根目录，
  让 `https://license.maning789link.top/MP_xxx.txt` 能被微信访问到，再点保存。
- 这个域名就是领码页 `GET /redeem` 所在的域名。协议里 `<授权域名>/redeem` 指向这里。

### 4.2 JS 接口安全域名（如需在前端调用微信 JS-SDK）

> 「设置与开发 → 公众号设置 → 功能设置 → JS 接口安全域名」

- 如果领码页只是纯 HTML 表单（协议 §6.2 规定自包含、无外部 JS/CSS），**不一定需要**配这个。
- 但若以后想在领码页里调微信 JS-SDK（例如拉起分享、获取网络状态），就要配，同样要上传校验文件。
- 建议现在先把网页授权域名配好，JS 接口安全域名按需再配。

> 校验文件放好后，微信校验偶尔需要几分钟；一直校验失败多半是校验文件路径不对或域名解析未生效，
> 用浏览器直接访问 `https://license.maning789link.top/<校验文件名>` 确认能下载到再回头保存。

## 5. 自定义菜单挂「领注册码」链接

让用户关注后能在底部菜单直接点进领码页。

> 「设置与开发 → 自定义菜单」（部分后台在「内容与互动 → 自定义菜单」，以实际为准）

1. 进菜单编辑页，选中一个菜单项（或新建一个）。
2. 菜单名称填「领注册码」或「免费领码」。
3. 菜单内容选**「跳转网页」**。
   - 服务号菜单跳转网页要求该 URL 的域名已在「网页授权域名」登记（§4.1）。
4. URL 填领码页地址：`https://license.maning789link.top/redeem`（与协议 §6.2 一致）。
   - 如果想让用户先经过网页授权拿 openid 再落到表单，URL 可以走微信网页授权中转：
     `https://open.weixin.qq.com/connect/oauth2/authorize?appid=<AppID>&redirect_uri=https%3A%2F%2Fmaning789link.top%2Fredeem&response_type=code&scope=snsapi_base&state=gt#wechat_redirect`
     （`scope=snsapi_base` 静默授权，用户无感，只拿 openid 不拿昵称头像）。
5. 点「保存并发布」。菜单发布后用户需**取关再关注**或在微信里重新进公众号才看到新菜单，
   不是所有用户立即刷新。

> 自定义菜单接口也支持用 API 批量配置（`POST /cgi-bin/menu/create`），适合菜单项多或要程序化维护时；
   手动配一两个链接用后台界面即可。

## 6. 关注自动回复与关键词回复（带领码链接）

让用户关注后立刻收到领码指引，以及回复关键词时也能拿到链接。

### 6.1 被关注回复

> 「内容与互动 → 自动回复 → 被关注回复」（部分后台在「设置 → 自动回复」，以实际为准）

- 编辑「被关注回复」内容，例如：

  > 欢迎关注稿台。
  > 免费领注册码：点击菜单「领注册码」，或回复「领码」获取链接。
  > 领到码后在客户端激活页粘贴即可使用。

- 注意自动回复**文本长度有上限**（一般约 600 字，以页面提示为准），超长会被截断。
- 文本里不能直接放可点击的超链接（微信文本回复不支持任意超链接），但可以放**已认证服务号关联的图文链接**或
  指引用户点底部菜单。要让链接可点，用「回复图文消息」或让用户点菜单（§5）。

### 6.2 关键词回复

> 「内容与互动 → 自动回复 → 关键词回复」

1. 点「添加规则」。
2. 规则名：`领码`。
3. 关键词：`领码`（可再加 `注册码`、`激活码` 等同义词，每个关键词一行）。
4. 回复内容：
   - 选「回复文字」：写「请点击底部菜单「领注册码」领取。」（文本里不能放任意超链接，靠菜单）。
   - 或选「回复图文」：从素材库选一条图文，图文里带领码页链接——但图文消息需先在素材库建好，较繁琐。
   - 最省事的做法：关键词回复引导用户点菜单，菜单跳网页领码。
5. 保存并启用。

> 关键词回复优先级低于被关注回复：新关注用户先触发「被关注回复」，之后回复关键词才触发关键词规则。

### 6.3 小程序卡片回复（可选）

如果领码页做成小程序页面，也可以在自动回复里回**小程序卡片**（`回复小程序`），用户点卡片直达小程序领码页。
但如 §0 所述，小程序不承担留存，只承担领码页/查状态，服务号才是留存主入口。

## 7. 群发能力边界：模板消息 / 订阅通知 vs 图文群发

服务号的触达能力有明确边界，别用错。

| 能力 | 图文群发（群发消息） | 模板消息 | 订阅通知 |
| --- | --- | --- | --- |
| 频次限制 | **每月 4 次**（服务号） | 无固定次数上限，但每次需指定接收人，且**只能在用户与公众号有交互后 48 小时内**或用户授权后发送 | 用户每次授权只能收到 1 条，授权一次发一条 |
| 接收对象 | 全部粉丝 / 按标签分组 | 指定单个或多个 openid | 指定 openid |
| 内容形态 | 图文（标题+摘要+封面+正文链接） | 固定模板的文字变量（如「您的激活码已发放」） | 固定模板，类同模板消息 |
| 是否需用户事先授权 | 否（群发即可） | 需在用户与公众号交互窗口内或用户主动授权 | 用户每次授权一次 |
| 适用场景 | 每月召回、版本更新公告、活动推送 | 服务通知：注册码发放、激活状态变更、到期提醒 | 同模板消息，适合一次性通知 |
| 在本方案的用法 | 每月用 1–2 次做版本/功能召回 | 领码成功后给用户推「注册码已发放」通知；到期前推送续期提醒 | 作为模板消息的补充，用户主动订阅后推送 |

要点：
- **每月 4 次图文群发是硬上限**（服务号），订阅号是每天 1 次但无网页授权。规划召回节奏时把 4 次当稀缺资源。
- **模板消息不是群发**，不能随便给所有粉丝发，只能给有交互/授权的用户发指定模板，适合做「领码后通知」「到期提醒」这类事务性触达。
- **订阅通知**是模板消息的演化形态，需要用户**主动订阅**（每次订阅对应一次下发额度），适合「激活到期提醒」这类用户愿意收的通知。
- 模板/订阅通知的模板需要在后台**先申请通过**才能用，见下一步。

### 7.1 申请模板消息 / 订阅通知模板

> 「功能 → 模板消息」（或「广告与服务 → 模板消息」，以实际为准）
> 「功能 → 订阅通知」（较新的后台，以实际为准）

- 从行业模板库里选或自定义模板，提交审核（通常较快，但以实际审核时间为准）。
- 模板里要留的变量字段，例如：`{{first.DATA}}`、`注册码：{{code.DATA}}`、`{{remark.DATA}}`。
- 审核通过后会拿到一个 `template_id`，填进授权服务器 `.env`，供「领码成功推送」「到期提醒」调用。

> 模板消息与订阅通知的接口与规则微信会调整，具体字段与调用方式**以当前微信官方开发文档为准**：
> `https://developers.weixin.qq.com/doc/offiaccount/Message_Management/Template_Message_Operation.html`

## 附：不确定、需要在后台确认的点

下列是我无法替你确认、需要你登录后台核对的地方：

1. **「自定义菜单」的确切入口**：部分后台在「设置与开发」，部分在「内容与互动」，名称偶尔变化——以你当前后台实际菜单为准。
2. **「自动回复」的确切入口**：同理，可能在「内容与互动」或「设置」下。
3. **IP 白名单可填数量上限**：微信文档称可填多个，但确切上限以页面提示为准。
4. **模板消息 / 订阅通知的后台入口名称**：较新的后台正在把「模板消息」过渡到「订阅通知」，两者并存，以你后台实际显示为准。
5. **被关注回复文本长度上限**：一般约 600 字，以页面字符计数提示为准。
6. **流量主开通门槛**（粉丝数、合规要求等）：微信会调整，以「广告与服务 → 流量主」页面当前提示为准。
7. **网页授权域名校验文件的文件名与内容**：每次「设置」时由微信生成下发，以页面当场给出的为准，本文无法预填。
