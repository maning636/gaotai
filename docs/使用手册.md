## 1. 篇幅：字数目标只管到选题和大纲

公众号的稿子天生是短的。写长了观点被稀释，读者也读不完。稿台**默认按 700–1200 字**来把握量级，
用户不写字数时也一样——不是「不设目标随便写」，而是有一个明确的量级。

**但这个目标只管两道工序。**

| 工序 | 字数目标怎么用 |
| --- | --- |
| 材料解读 | 不用 |
| 选题与方向 | 建议的「适合篇幅」要落在这个量级上 |
| 写作大纲 | 各段的「篇幅」相加要对得上末尾的总账 |
| 文章正文 | **不设目标**：正文提示词里一个字数都不给 |

正文阶段为什么不给，作者 2026-10-23 讲得很直白：「到最后你限制他输出有个屁用啊」
「你还在那追究个屁的字数啊」。

正文的产出质量取决于两件事——**大纲里那条线立不立得住**、**技能包里的写法有没有被用上**；
不在于提示词里有没有一个字数。硬塞一个数字进去只会多两件事：
模型为了凑数而重复解释，以及稿台自己跟自己较劲（限制输出 = 制造返工）。

所以稿台的做法是**从类型上就不可能**给正文塞字数指令：
`renderLengthInstruction()` 的参数类型里没有 `article`——不是「正文分支返回空」，是根本传不进来。
大纲末尾那行「总字数估算」和各段的「篇幅：xxx 字」也不会流进正文上下文
（`stripLengthLines()` 会在整份带上原文时把它们去掉）。

字数目标本身还在，两个地方用：

- **算输出额度**（`generationBudget()`）：目标越长额度给得越多，免得写到一半被截断。
- **成稿体检报告**里显示「距目标多少字」：只是参考量级，不是合格线。

### 1.1 这个数从六个地方找，按优先级从高到低

| 优先级 | 来源 | 说明 |
| --- | --- | --- |
| 1 | 界面上手填的「目标字数」 | 最明确：「1000」「800-1200」「1200 字左右」都认 |
| 2 | 本次输入里明确在谈篇幅的那句 | 「写 1000 字左右」「全文 1200 字」 |
| 3 | 已确认大纲的总字数估算 | 大纲末尾那句「总字数估算」 |
| 4 | 选题阶段给的「适合篇幅」 | 选题本来就该知道自己这篇该多长 |
| 5 | 材料解读里定的篇幅 | 最后才轮到这个 |
| 6 | 默认 700–1200 字 | 公众号是短文 |

### 1.2 默认篇幅是硬边界，不只是兜底

真模型实测（2026-10-23）：大纲阶段明明白白被要求「各段相加落在 700–1200 字」，
它交出来的总账是 **1520–1920 字**——八段，每段 180–300 字，每段单看都合理，加起来却越了界。
**提示词管不住模型，规矩得由代码来守。**

所以 700–1200 这个区间同时是**上限**：

- 模型自己写的数（大纲的总账、选题的适合篇幅、材料里定的篇幅）**只能在区间里收窄，推不出去**。
  区间相交就用交集（模型给 900–1100，就写 900–1100）；整段超出上限就按 700–1200 写。
- **整段比下限还短时照旧的**：材料撑不住的时候，一篇短而实的稿子比一篇注水的稿子有用，稿台不硬凑。
- **用户自己说的数不受限制**：界面上手填的「目标字数」，或者输入里明确在谈篇幅的那句，
  都是作者自己的意图，作者说了算（想写长篇就手填一个 3000）。

大纲阶段还多给了一句具体的分法：**「大约分 4 段，每段 175–300 字」**。
只说「落在这个数上」不够——模型照样会分八段、每段 200 字，加起来一千六；
把段数和每段多少字直接摆给它，它才知道该分几段。

### 1.3 另外几条实测出来的规矩

- **输入里的字数，默认不算篇幅目标。** 输入常常就是两千多字的原话，里面「大概 2500 字」说的是
  **素材有多长**，不是稿子要写多长。稿台只在同一句话里同时出现「谈篇幅的词」（写 / 正文 / 成稿 /
  全文 / 篇幅 / 字数 / 控制 / 不超过 / 至少 / 最多）和字数时，才把它当目标；
  句子里有「素材 / 原文 / 摘抄 / 聊天记录 / 笔记」这类词，整句跳过。
  判不准的时候，界面上的「目标字数」输入框是兜底——它怎么写都认。
- **目标会写进提示词，而且写清它从哪来**——但只对选题和大纲两道工序。
  模型知道「默认篇幅是 700–1200 字」，也知道「用户要求是 2000 字」，不会自己另立一个标准。
- **大纲有三种写法，稿台都认。** 模型有时按模板写结构式
  （`**第 1 段 · 钩子**` + 目的 / 内容 / 素材 / 篇幅 / 形式），有时写成散文式
  （`**开头怎么进**` / `**中间几段分别讲什么**` / `**结尾落点在哪里**`），
  有时又写成 markdown 标题（`## 第 1 段 · 钩子` + 下面几行不带符号）。
  只认一种的话，另两种的段落会**整段消失**——
  分节写作拿不到段落，退路失效，正文阶段就只剩「干等」。
  所以三种都解析，优先用带字数账的那种。
- **解析器必须比提示词更宽容。** 改一次提示词，模型就换一个写法：
  2026-10-23 提示词里写的是引用块形状，模型交回来的是 `## 第 1 段`，
  行首的 `##` 没被剥掉 → 标题不匹配 → 解析出 0 段 → 分节退路失效 →
  正文阶段空等 6 分钟才报错。
  所以段落标题的装饰（引用块 / `#` / 粗体 / 列表符）在切段之前统一剥掉。

## 2. 大纲里先定「谁在说」

大纲开头除了**全文主张**和**全文推进线**，还有一块**说话位置**（四行）：

```
**说话位置**
- 谁在说：一个把公司代码库迁到自研编辑器的人
- 凭什么知道：他迁过三次，三次都自己写的脚本
- 他的判断：值不值取决于团队里有没有第二个人会写
- 读者的追问：那我该按什么标准决定迁不迁
```

这是枪手 skill 里的方法：**动笔前先找到说话位置**。它决定这篇稿子是谁在说话。

- **谁在说**不要写「一个从业者」这种谁都能贴的标签；
- **凭什么知道**要落在材料真给得出来的东西上；
- **他的判断**是一个具体的、可能有人不同意的判断；
- **读者的追问**要是读者真的会问出口的话。

**这四件事在大纲阶段一次想定，正文阶段直接照着这个人的口气写。**
放在正文阶段想有两个坏处：一是要占额度（正文阶段的思考额度已经被内容挤满了），
二是模型每写一段都要重新想一遍「我是谁」，各段的语气会飘。

稿台解析这块时要求**四行齐了**才算数；缺行就不给，正文退回「按一个真正干过这行的人写」，
不替模型编。分节生成时（每一节都是独立请求）也带着它，否则每节自己挑一个语气，
拼起来像几个人写的。

## 3. 正文阶段不纠缠字数，也不给模型工具

正文阶段的提示词里没有字数，也**不给模型任何工具**。这两条都是踩着真模型的坑改的。

**不给字数**：见上面「篇幅」一节。

**不给工具**：以前这里给过体检工具（`check_prose`），让模型写完初稿自查一遍再改。
现在不给了，两个原因：

1. 稿台自己就在成稿后跑一遍体检（`reportArticle`），结果照旧展示给用户。
   模型再自查一遍，是同一件事做两遍。
2. **「写完自查再改」是一条程序型指令**——它要求模型在思考里执行一套「检查—修补」的流程。
   真模型实测（2026-10-23）：正文请求带这种指令时，思考额度被吃光、正文一个字都没有。

技能包的写作方法改由**服务端注入**（见第 6 节），不依赖模型调工具。
决策记录见 [`architecture/decisions/0002-prose-stage-no-tools.md`](architecture/decisions/0002-prose-stage-no-tools.md)。

## 4. 中间产物也要短

**只有正文是交付物，其余三道工序是施工图。** 施工图比交付物还长，说明它写成了草稿。

真模型实测（2026-10-23 03:00，一篇 900 字的稿子）：

| 工序 | 产物 | 耗时 |
| --- | --- | --- |
| 材料解读 | 2269 字 | 22 秒 |
| 选题 | 2288 字 | 16 秒 |
| 写作大纲 | **1788 字** | 142 秒 |
| 文章正文（目标 900 字） | **0 字，失败** | **10.3 分钟** |

大纲比正文长一倍，而正文那一阶段**十分钟都没写出来**。两个问题是同一件事：

- 大纲的每一段里，「内容」字段是 200 多字的**散文**——模型在大纲阶段就把正文写了一遍，
  到正文阶段再写一遍。施工图写成了草稿。
- 正文阶段的请求上下文 ≈ 系统提示 + 材料解读 2269 + 选题 2288 + 大纲 1788 ≈ **25KB**，
  而交付物只有 900 字（1.8KB）——上下文是交付物的 14 倍。
  上下文越长，模型陷进长上下文的思考里越深，输出额度全被思考吃光，正文一个字都没有。

所以稿台给三道中间工序**各自定了一个字数上限**，跟正文的目标是两回事：

| 工序 | 产物上限 | 为什么是这个数 |
| --- | --- | --- |
| 写作大纲 | 700 字 | 4 段 × 每段 150 字，够写清推进 / 目的 / 素材 / 形式，再加开头那三块 |
| 选题与方向 | 700 字 | 3 个角度 × 每个 160 字 |
| 材料解读 | 800 字 | 事实、判断、疑点、缺口各一小节 |

大纲这一项还额外钉死了**每个字段**的宽度：「内容」不超过 40 字、
「目的」「素材」「形式」各不超过 25 字，一段加起来不超过 100 字。
只给整份大纲一个上限不够——模型会在某一段里写满散文。

这个上限是**写进提示词的具体数字**，不是一句「写短点」——
模型分不清「正文的字数目标」和「这份大纲自己该多长」，不给数字它就按前者来。

### 4.1 正文阶段不再空等

正文阶段一次生成空正文时，稿台**不再重试**（重试三次等于白等六分钟，
而且每次都要把越滚越大的上下文重发一遍）：

- **有已确认的大纲** → 一次不行就换路：有大纲段落就走分节生成，
  没有就干脆快速失败——让用户早点看到原因，比干等六分钟强。
- **没有大纲** → 留着重试。那时没有别的路可走，空正文没有第二次机会。

### 4.2 正文阶段只拿必要的上下文

写正文真正需要的只有两样：**这一段要干什么**（大纲的结构）和**材料里的硬事实**。
选题阶段的论证过程已经被大纲吸收了，带进来只会让正文复述一遍。

所以正文阶段不再把前序产出全文灌进去，而是：

- 大纲只取结构化部分（每段的角色、目的、素材、篇幅、形式）——
  不取原文里的散文，那是在大纲阶段就把正文写了一遍的东西。
- 材料解读只取「硬事实」一节——写正文时能引用的数字、事件、原话都在这儿，
  这是「不编造」的最后一道保险。
- 选题阶段**不带**。

## 5. 长文走分节生成

目标超过 2400 字时，稿台不再一次性写完，改成**按节写**（`src/lib/section-writer.ts`）：
每一节几百字，三节并发，每节一个独立的字数账（「控制在 N 字上下」实测能精确命中）。

一次性写长文有两个毛病，都是真模型实测出来的（2026-10-23）：

- **不稳**：同一条 3500 字的请求连着跑 4 次，3 次一个字都没交出来，每次白等两分钟。
- **长度对不上**：交出来的那次只写了 2066 字，正好等于上下文里上一稿的 2068 字——
  模型是照着旧稿的长度写的，让它写 3500 它就写 2000。

所以正文阶段一次生成空正文时，稿台**不再重试**（重试三次等于白等六分钟），
直接改走分节生成，并在界面上说明这一版是怎么写出来的。

分节生成不经过技能工具（八个请求没法各读一次技能包），但会把技能包里
「第一稿直接带着人写」那一节带进每一节——带上它，模型第一遍就少写模板腔。
整份技能包**不**带进去：里面有「先列清单再动笔」的内部自查指令，会诱发思考螺旋
（额度被吃光、正文全空）。分节时也会把「说话位置」一起带上：每一节都是独立请求，
不带这个的话每节自己挑一个语气，拼起来像几个人写的。

**这条路的实测状态（如实说）**：在 SenseNova 6.8 上，长目标（3000 字）目前交不出正文——
无论一次性写还是分节写，模型都会把额度全花在思考上（`reasoning_tokens` 等于额度，正文 0 字），
额度给到 32768 也一样。这条路是为「模型写不动长文」准备的退路，
在能写长文的模型上才有意义；公众号日常的 700–1200 字不经过这条路（实测 9.7 秒、984 字、零硬禁令）。

## 6. 技能包

写作方法最容易变成「一大段塞进提示词」的东西：又贵，又稀释注意力，还容易互相打架。
稿台的做法是**按需读取**——只把技能入口告诉模型，让它自己决定读哪几份参考文件。

```
resources/skills/<技能名>/SKILL.md          入口，含 YAML 头（name / description）
resources/skills/<技能名>/references/*.md   参考文件，由 SKILL.md 自己指路
```

几条规则：

- **在材料解读与正文两个阶段启用**。中间两道工序要的是判断和结构，塞一份几万字的写作方法只会让模型分心。
  材料解读阶段能挂技能包，是因为输入常常是两千多字的原话——「怎么总结、总结成什么样」
  正是要一份专门的技能包来管的事（作者自己写一份总结用的 skill 就行）。
- **材料解读阶段由模型自己读**。系统提示里只列出有哪些技能、入口在哪，
  模型用 `read_skill_file` 工具按需读取。这个工具不联网、不执行脚本，只读本机文本。
- **正文阶段由服务端注入「写作方法」那一节**。这一条是踩着真模型的坑改的：
  让模型先跑工具读 15KB 的 `SKILL.md`、可能再读 24KB 的参考文件，
  每轮都要把这些重发一遍——真模型实测（2026-10-23）：这么走一轮是 **10.3 分钟**，
  额度全被长上下文的思考吃光，正文一个字都没有。
  所以稿台改成：服务端直接把技能包里的「怎么写」那一节读出来，放进正文提示词。
  **注入的是方法，不是禁令清单**——注入「成稿绝对不能出现」那一节时，
  实测 16384 的额度被 `reasoningTokens` 吃满、正文 0 字、`finish_reason=length`：
  清单会让模型逐条核对，额度全花在思考上。方法给出路，禁令只给墙。
- **正文阶段不给模型任何工具**（含体检工具）。原因见第 3 节：
  「写完自查再改」是程序型指令，思考额度会被吃光。稿台自己量一遍就行。
- **读得到什么由路径安全兜底**：只接受相对路径，拒绝绝对路径、`..` 与控制字符；
  逻辑路径和真实路径各校验一次，符号链接不能把读取带出技能目录；没启用的技能直接读不到。
- **没真正生效会明说**。文件躺在磁盘上不等于这次用了它——
  材料解读阶段如果模型压根没调工具，稿台会在界面上提示「这次不是按技能要求写的」，
  而不是默默当作合格产出。正文阶段则看有没有取到那节写作方法。

界面在稿件页的「技能包」区块：看得见有哪些技能、各自管什么、里面有哪些文件，
勾选哪些由你决定。专题可以在 `meta.yaml` 里用 `skills:` 声明默认启用的技能。

现在装着三个：

| 技能 | 来源 | 管什么 |
| --- | --- | --- |
| `gaotai-longform` | 本仓库自研（作者自己的写作方法整理而成，AGPL-3.0-only 或 MIT 双许可） | **公众号长文怎么写**：主导推进线、前三屏、技术段落的六件事、段落节奏、作者声音、交付前删除优先审查 |
| `human-writing` | 第三方，MIT（见 README「许可证与第三方」） | 通用中文长文写作：材料够不够、禁翻案腔、禁商业与模型黑话 |
| `gaotai-editorial` | 本仓库自研（AGPL-3.0-only） | 成稿之后的三件事：标题打磨、开头重写、事实核查 |

**公开专题默认启用的是 `gaotai-longform`**（`meta.yaml` 里的 `skills:`）——
正文阶段注入的那节「怎么写」就来自它。技能包在激活后经授权服务器下发并缓存到本机，
`human-writing` 需要的人可以在界面上手动勾上。

> `gaotai-longform` 的来路与处理见 `resources/skills/gaotai-longform/NOTICE`：
> 它出自作者本人的写作方法，**去掉了作者的个人偏好记忆**（文风、视觉审美），
> 也去掉了引用第三方作品时留下的具体账号与链接，只保留可迁移的叙事机制。

想加自己的技能：在 `resources/skills/` 下建一个目录，写好 `SKILL.md`（YAML 头里的 `name`
必须等于目录名）和 `references/`，重启即可。

## 7. 接模型服务

稿台直连 OpenAI 兼容的 `/chat/completions`，填 Base URL、API Key、模型名就能用。
下面几条是接真模型时踩出来的，都写在代码里，不是文档里的注意事项：

- **思考型模型会把输出额度吃掉。** 带 reasoning / thinking 的端点把 `max_tokens` 花在
  思考上，正文可能一个字都不剩——用户看到的是「生成成功，内容是空的」。
  实测（SenseNova 6.8）：改稿请求一次要 2000 字，8192 个额度全进了思考字段，
  正文返回空串，`finish_reason` 是 `length`；额度加倍到 16384 之后**还是空**
  （16384 个 token 继续进了思考）。
  所以稿台分两种截断处理：**写了一半**（有内容）才加倍额度重来；
  **一个字都没有**时加倍是在喂思考，稿台改成**换打法再试**，最多两次——
  换一个**没试过的**思考强度，再把温度抬高一档换一条采样路径。
  这里不能固定往一个方向降：`none` 和 `minimal` 各有各的形状适用（见下一条），
  固定降级会把某一种形状推进坑里。
  实测这个端点会随机陷进同样的思考螺旋：angle 阶段带着 `minimal` 连着三次 0 正文，
  同一请求单独再打一次却一次就成了（1645 字）。
  两次都拿不到正文，稿台会直接报错说明原因，而不是交一份空稿。
- **额度给够，别抠着。** 每个阶段都按 8192 的额度发。实测同一条 angle 请求，
  额度 4096 时模型花了 2031 个 token 思考、写了 1645 字；额度 8192 时思考只花 307 个 token、
  36 秒就写完 2082 字。额度紧的时候模型更容易把额度全花在思考上。
- **思考强度没有「哪个更好」，只有「哪个形状用哪个」。** 模型页有一项思考强度
  （跟随模型默认 / minimal / none / low / medium / high / max）。默认选 `minimal`。
  同一份提示词、同一份额度，只换这一个变量的实测：
  - **一次性写正文**：`minimal` → 思考只花 257，正文 984 字，9.7 秒；
    `none` → 思考把 8192 额度吃满，正文 0 汉字。
  - **按节补写**：`none` → 思考 3005，正文 74 字；`minimal` → 思考吃满额度，正文空。
  所以稿台在正文阶段不硬写死强度（跟模型配置走），空正文时在 `none` 与 `minimal` 之间
  **轮换**着试，总有一个是这个形状能用的。
  端点不认这个参数时会自动去掉它重试，并且记住这个端点不认，以后不再发这个字段，
  不会每次请求都白跑一趟。
- **模型写不出「凭空的长文」，但写得出「有据可依的段落」。** 实测：让模型凭空写一段
  300 字的中文，它把额度全花在思考上、正文一个字没有；让它在已有内容后面接着补，
  或者照着一段大纲要求写，它十几秒就交稿。
  所以补写是**按节**做的（见第 5 节「长文走分节生成」），一次只让模型产出一节。
- **模型可能把工具调用写进正文里。** 有些端点不返回结构化的 `tool_calls`，
  而是把调用写成一段文本（实测 SenseNova 6.8 就有这毛病）：
  `<tool_calls><invoke name="read_skill_file">…</invoke></tool_calls>`。
  不认它的话，这段 XML 会原样变成这一阶段的正文——
  「材料解读」存进去的是一段工具调用，后面每一道工序都拿着它当素材，
  模型只好回你一句「我这边没有拿到材料」。
  稿台认得这种写法，照常执行工具、把结果喂回去，循环继续走。
- **模型可能反复调用工具。** 它读完技能文件、写下初稿、自查一遍，往往还想再读一次，
  于是绕起圈来。稿台对「同一个工具、同样的参数」不重复执行，直接告诉模型结果已经给过；
  最后一轮之前提醒它收尾。万一轮次还是用完，稿台交出模型写的最后一版并说明它没收尾，
  而不是抛错把整篇稿子丢掉——模型要是把正文写在了体检工具的参数里，稿台会把那一版取回来。
- **服务会限流。** 带 RPM / TPM 限制的服务商在长文生成时必然返回 429。稿台遇到
  429、502、503、504 会指数退避后重试（最多 4 次），别的错误（比如模型名写错）
  一次就报清楚，不让用户白等。

模型服务不支持工具调用时，稿台降级成普通对话，并在界面上说明「这次正文没有按技能包的要求写」，
不假装技能生效了。

实测可用的配置（商汤 SenseNova 开放平台）：

| 项 | 值 |
| --- | --- |
| Base URL | `https://token.sensenova.cn/v1` |
| 模型 | `sensenova-6.8-flash-lite`（模型名全小写） |
| 鉴权 | `Authorization: Bearer <你的 sk- 密钥>` |
| 思考强度 | 写长文建议 `minimal` |

`temperature` 可以照常传；`max_tokens` 是「思考 + 正文」的总额度，正文长篇时要留够。

## 8. 查 AI 味

成稿写完，稿台可以给它做一次体检，把模型腔揪出来。规则来自 human-writing 技能包自带的
`check_prose.py`（MIT），这里做了一份原生实现——桌面客户端不能指望用户机器上装 Python。

体检分两档，每一条都带行号：

- **必须修改**：中文冒号、破折号、「不是……而是……」翻案句、硬停词（「说白了」等）、
  绝对禁用黑话（「赋能」「抓手」「底层逻辑」等）、模型路标（「值得注意的是」等）。
- **需要人工判断**：要结合语境看的词、翻案腔变形、三连同构排比、名词化句式、
  连词密度、句长过于整齐、单句段过多、固定开场、多套比喻。

体检**只报警，不改文**——改的时候要先找句子原本想说的事，再用普通句子说出来，
换成另一种漂亮句式没有用。

正文阶段交稿之前，服务端用同一把尺子量一遍（`src/lib/article-review.ts`），
但**量完只出一份报告，不退回、不改写、不补字**。稿子是模型写的，稿台不替人搓。

- **这里原本有一道服务端闸门，现在没有了。** 旧做法是：量一遍，不合格就让模型改一轮
  （去重 → 按句改写 → 按节补写 → 两版挑一版）。这套机器被拆掉了，三个理由：
  - 真模型实测（2026-10-23）：整篇重写和补写在这个端点上极不可靠，
    额度全被思考吃光、正文一个字交不出来，等一圈下来什么也没改成。
  - 改写会顺手把稿子改短、改钝——「冒号少了但字数更短了」真实发生过，
    改坏比不改更麻烦。
  - 用户要的是一份能自己判断的稿子，不是一份被机器来回搓过的稿子。
    尺子量出来的问题摆在那里，怎么改是人来决定。
- **合格线从「字数够不够」换成「大纲要点有没有落地」。** 字数不是合格线：
  材料撑得起就写实，撑不起就写短，写短是合法的。
  大纲上规划过的内容有没有进正文，才是「这篇写完了没有」的真正口径。
  这一层是**纯机械**的（`src/lib/outline-coverage.ts`）：不调模型、只提示、不拦路。
  - 判据是**锚点命中**：数字和英文词（800、1.29、Kubernetes）在正文里出现就算落地。
    只认这两类是有理由的——它们在正文里几乎会原样出现，而纯中文措辞在正文里必然换说法
    （大纲写「评审变慢」，正文写「评审那部分卡得更久」），拿它当判据会大量误报。
    误报比漏报更糟：用户会照着提示去改一篇其实没问题的稿子。
  - 抽不出锚点的段（比如只写「引入问题」）不参与判定——没有可核对的锚点，判了也是瞎判。
  - 命中一个就算落地：这一段的目的可能很宽（"讲清楚为什么慢"），
    正文里的说法又必然跟大纲措辞不同。要求全中会把大量写到了的段落误判成漏写。
  - 大纲里那句「材料第 3 段」不参与判定：留着它等于给每一段发一个「3」，
    正文里随便哪个数字都能命中，等于没判。
- **重复表达由机械量出来，人来改。** 稿台分五档量重复：逐字重复、高度相似、
  一句包着另一句、整段短语重复、段落级重复。报告里如实列出，稿台不动手删——
  模型改写只会把同一句话换成另一种说法再出现一次，那句话还在，只是换了个说法。
- **字数目标仍然显示，但只是参考量级**，不是配额：材料撑得起就写实，撑不起就写短。
  正文提示词里根本没有这个数（见第 1 节）。

界面上会逐条显示：字数、大纲要点覆盖（几段落地、哪几段没落地）、
必须修改与需要人工判断的条目。慢在哪儿也看得见：每一次模型请求都记下标签与耗时，
产出面板上直接显示「用了 X 分」。

一个入口：稿件页正文下方的「查 AI 味」按钮，结果直接列在页面里。
（模型自己调 `check_prose` 自查这条路已经拆掉了——「写完自查再改」是程序型指令，
思考额度会被吃光，见第 3 节。）

## 9. 公众号闭环

### 9.1 排版已有文章（跳过前三道工序）

文章早就写好了、只想排一下版发出去？工作台上有「**排版已有文章**」：

- 贴 Markdown **或者**从公众号后台复制的 HTML 进去；
- **只走最后一道工序**——文章直接进正文阶段，材料解读、选题、大纲全跳过
  （文章已经是写好的，那三道工序对它没有意义）；
- HTML 会**自动洗成 Markdown**（标题、加粗、链接、图片、引用、列表都保住，
  颜色字号这些样式丢掉——那是排版模板的事）；
- 标题留空就从文章里猜（优先取第一个一级标题）；
- 导进来照样能：选排版模板、看公众号预览、推草稿箱。

> **外链图会被收进本机**：公众号**不接受外链图片**，正文里写 `![](https://…)`
> 推上去之后那张图会变成空白。所以推草稿之前，稿台会把外链图先下载到本机素材库，
> 再换成微信自己的地址。下载前会检查目标是不是内网地址——
> 软件是本地的，但用户会往里贴任意网址，不挡就成了「用软件读内网」的工具。

### 9.2 从 Markdown 到草稿箱

Markdown → 公众号兼容 HTML（只有行内样式，没有 class）→ 草稿箱 → 你自己去后台预览与发布。
稿台不代替人点发布。另外提供已发布文章同步与图文数据统计。

推上草稿箱之前，稿台会替你处理两件**不做就一定推坏**的事：

- **封面**：公众号草稿必须带封面（`thumb_media_id`），它是微信**永久素材**的 id。
  在「公众号」页面上传一张封面，稿台会把它存进本机素材库、上传到微信换一张封面凭证，
  凭证写进 `.env` 的 `WECHAT_THUMB_MEDIA_ID`，之后每次推送复用它——
  永久素材有每日新增额度，不重复上传。
- **正文图片**：正文里引用的本机图片（`/api/files/img/…`）公众号服务器根本访问不到，
  推过去就是一片空白。稿台在推送时逐张换成微信自己的图片地址，
  走的是「上传图文消息内的图片」接口，只换地址、不占素材库配额。
  某张图失败不阻断整篇，但会在界面上点名是哪几张没上去。

排版上有三条专门针对公众号的处理：

- 代码块的换行写成显式 `<br />`，不依赖公众号保留 `<pre>` 的空白样式——
  靠空白保换行的话，代码到了公众号里会塌成一行。
- 输出只有行内样式、没有任何 `class`，因为公众号编辑器不认样式表。
- 正文里的链接只给 `http/https` 生成 `<a>`，其余协议（`javascript:`、`file:` 等）一律降级成纯文本，
  只留链接文字。公众号正文里点链接是平台红线，稿台不主动制造站外跳转；
  至于贴进公众号后还能不能点，由平台自己决定（微信会剥掉 `href`）。

### 9.3 先测后发：没测通就不许推草稿

「公众号」页面上填完 AppID / AppSecret，会当场做一次**通道测试**：
拿凭据换一张 access_token——这一次请求同时验了三件事：凭据对不对、
本机 IP 在不在公众号后台的白名单里、这个账号有没有草稿箱接口的权限。

**测不通，「推到草稿箱」就是灰的**，服务端也拦得住（直接打接口一样推不出去）。

微信的报错是一串错误码，稿台把它翻成人话：

| 微信说 | 稿台说 |
| --- | --- |
| 40164 | 本机出口 IP 不在白名单里，并**直接把微信看到的那个 IP 报出来**（不用用户自己去查公网 IP） |
| 40125 | AppSecret 不对（Secret 只显示一次，重置过要用新的） |
| 40013 | AppID 不对 |
| 48001 | 这个账号没有草稿箱接口的权限（未认证订阅号用不了），并建议改用「复制排版正文」 |
| 45009 | 调用太频繁 |

> **一个绕不过去的坎**：微信要求调用方的**公网 IP 在白名单里**，而白名单只认
> 最多 20 个**精确的 IPv4**，不支持域名或 IP 段，改完还要等 5–10 分钟生效。
> 家宽 IP 是动态的，填了也会失效。稿台能做的只是**把卡在哪一步说清楚**——
> 要真过这一关，得有固定出口 IP（固定 IP 宽带、或一台有固定 IP 的小机器做中转）。
> 不想折腾就用「复制排版正文」，零门槛。

### 9.4 排版配色与复制

三套配色自由切换：**深灰**（默认）、**暖纸**、**雾蓝**。

- 三套**共用同一套结构**：段落、标题、引用、代码块、表格的骨架一字不改，换的只是色值。
  所以切主题不需要重排版，改一个值重渲染一遍就行。
- 标题字重 500、正文左对齐（不做两端对齐——中文两端对齐会在标点处挤出错位）、
  引用块左边线、代码块是三色圆点的窗口卡片、表格带横向滚动框（窄屏不挤成一坨）。
- 主题**按稿件记**：稿件页正文下方是「排版：当前模板名」+「换排版」按钮（跳 `/templates` 模板库页），公众号面板推草稿时也能切换。
  选了主题推草稿，推上去的就是那套配色；草稿内容没变时不会重复推送（见 9.6）。
- 「复制排版正文」一次写两份进剪贴板：html（带行内样式）和纯文本。
  贴进公众号编辑器走 html 那份，贴进纯文本编辑器走文本那份——
  只写一份的话，用户换个地方粘贴就变成一堆标签。

排版模板的部件模型、样式包清洗规则与「选哪套」的优先级，权威口径在
[`spec.md` §1.4](spec.md#14-排版模板)。

### 9.5 模板库：怎么挑、怎么看、怎么应用

正文页原来有个「排版」下拉框——只能看见名字、看不见效果，挑一套要来回几轮。现在「挑模板」
收进了模板页（`/templates`）的「模板库」Tab，编辑器和公众号面板里的排版选择都跳到那里。
同一页还有「模板管理」Tab：导入样式包、取舍部件、改色、存自己的模板（原来的 `/layout` 页面），
`/layout` 旧链接会自动跳到这个 Tab。

**怎么挑**：模板库页两栏。左边是平铺的卡片网格（不再是下拉框），每张卡有：模板名、来源徽标
（**内置** / **随包** / **WeDraft** / **我的**）、一句描述、按该模板渲染的缩小预览、以及
「当前」标记（这篇稿件正在用的那一套）。点卡片**只更新右边的手机预览，不会立即应用**——
所以你可以点着比较，不会误改到稿件。

**手机预览怎么看**：右边是一台 iPhone 外形（屏幕 440×956），顶上有状态栏和微信顶栏，
屏幕里按同一份示例稿渲染出你选的那套排版，可上下滚动。窄屏（<1024px）时手机会折叠到卡片列表
下方或弹层，不遮卡片。

**手机框是模拟，不是真的微信**：预览是「CSS 手机外框 + 示例稿按模板渲染」，字体渲染、行高压缩、
Emoji、iOS/Android 微信的差异化一概不模拟。真机效果要看两个地方：

1. **复制排版正文** → 贴进公众号编辑器，最真实；
2. **推草稿** → 草稿箱里看（要过 IP 白名单，见 9.3）。

模板库页的手机只回答「结构和色值是不是我想要的」，不回答「微信里长得对不对」。

**模板管理怎么用**：切到「模板管理」Tab。左边是小方块瓦片（两列），点一个就在中间打开它的配置；
中间改颜色、勾部件、改 HTML，右边的手机**实时**跟着变；自定义模板可保存/删除，内置模板点
「复制一份来改」。顶部「导入样式包」仍能收外部 JSON。

**怎么应用**：手机下方有「使用这套」按钮。带 `?project=<id>` 进入模板库时（编辑器点「换排版」就是
这么带的），点了会把这篇稿件的模板记下来，然后跳回 `/projects/<id>`；编辑器按既有逻辑重新读取
并重新渲染。不带 `?project` 时，「使用这套」不会绑定任何稿件——纯挑看。

**想去改 / 导入 / 删除模板**：模板库页头部有「管理模板」链接跳到 `/layout`。管理页是
「导入样式包 → 取舍部件 → 编辑色值 → 存为我的」的全家桶，不适合当浏览页。模板库只做
**看与选**，`/layout` 只做**管**，两页职责不混。

**WeDraft 那 7 套从哪来**：卡上带「WeDraft · 素笺」这类来源前缀的模板，是从
[pafa/WeDraft](https://github.com/pafa/WeDraft)（MIT，Copyright (c) 2026 pafa and WeDraft
contributors）翻译过来的 7 套：`reading-editions.ts` 的 5 套（素笺 / 墨刊 / 青岚 / 蓝图 /
朱砂）+ `default-business.json`（小哈公社）+ `next-edition.json`（小哈公社 New）。
MIT 版权与许可声明随包保留在 `resources/layout-packs/`（`LICENSE-wedraft` + `SOURCE-wedraft.json`），
汇总见根 [`NOTICE.txt`](../NOTICE.txt)。

WeDraft 用「元素 → CSS 声明」，稿台用「部件 → HTML 模板」，转换按
[ADR-0004](architecture/decisions/0004-template-gallery.md) 的映射表把 `article`/`heading2`/
`paragraph` 等元素归到稿台的 `root`/`heading`/`paragraph` 部件。装饰类的能力（`headingNumber`
章节序号、`quoteMark` 引用装饰符、`imageCaption` 独立图注、`reference*` 参考文献）在稿台的部件
模型里没有对应位置，第一版转换一律丢弃，记录为已知限制。

### 9.6 推草稿是幂等的

稿台记着这份稿子的内容指纹。内容没变就什么都不推（直接回原来那份草稿的 id），
变了才更新那一份，不会推两次就在草稿箱里躺两份。

### 9.7 本地假服务器跑通整条链

想对着本地假服务器把整条链跑通（不需要公众号凭据，也不需要 IP 白名单）：

```bash
GAOTAI_WECHAT_API_BASE=http://127.0.0.1:3099 npm run dev
```

`GAOTAI_WECHAT_API_BASE` 只用来把接口基址指向本地，默认是官方的 `https://api.weixin.qq.com`。

### 9.8 随包主题的翻译与授权边界

排版模板页的「随包主题」那一组，是从
[ricocc/rico-md](https://github.com/ricocc/rico-md)（Rico 的公众号排版编辑工具，MIT）
的 21 套主题**翻译**而来的衍生作品：素灰·清水、赤陶·有机、墨蓝·卫报、赭红·编辑、
Kami 紙、素白·留白、编辑部红、素墨·世界报、简约沉浸、朱红·日经、Claude、
Apple 极简、深度阅读、默认公众号风格、优雅简约、金融时报、纤细极简、Medium 阅读、
墨线·报纸、纸纪、技术风格。

翻译不是照抄：

| 做了什么 | 为什么 |
| --- | --- |
| 上游是「选择器 → CSS 声明块」，这里按稿台的**部件模型**重新组装 HTML | 标签与占位符换成稿台自己的（`{{content}}` 放内容、`{{变量名}}` 取色值） |
| 去掉 `!important` | 行内样式里没有意义，而且 `!` 不在稿台清洗器的白名单里，留着会让**整条声明被丢掉** |
| 去掉字体栈里的双引号 | 双引号同样会被清洗器当成非法字符 |
| 颜色提取成变量 | 所以「改一个色值全篇跟着变」在导入的主题里同样成立 |
| h2/h3/h4 拆成三个部件 | 上游给每一级标题配的样式差别很大（字号、边框、斜体、大写），合并会把层次抹平 |

> **授权边界**：rico-md 主体是 MIT（Copyright (c) 2024-2026 Rico），
> 但它新增的 `gzh-design-skill` 主题适配模块（`assets/styles/themes/gzh/`）是
> **AGPL-3.0-or-later**（甲木 × 摸鱼小李）。稿台当前采用 AGPL-3.0-only，
> **那 12 套 AGPL 主题仍整套没有引入**。MIT 要求保留版权声明与许可声明，
> 因此 `resources/layout-packs/` 下同时带着 `LICENSE-rico-md` 与 `SOURCE.json`
> （含逐条说明：引了什么、没引什么、为什么没引）。

### 9.9 以后看到别的排版模板，怎么接进来

这是一条**可重复的流程**，不是一次性操作：

```bash
# 1. 下载上游主题（选 MIT / Apache / BSD 许可的；AGPL 与无许可的不要碰）
# 2. 翻译成稿台的样式包
python scripts/translate-theme-to-pack.py <主题目录> resources/layout-packs <前缀> <上游标识>
# 3. 放进 resources/layout-packs/ 即成内置模板；编译打包后随安装包分发
```

翻译器要求上游主题是「**选择器 → CSS 声明块**」的形状
（`{ name, styles: { h1: "声明;声明;", p: "…" } }`，选择器名用标准 CSS 名）——
大多数排版主题都长这样。

**接之前先查许可**：MIT / Apache-2.0 / BSD 可以翻译可分发，但要保留版权声明与许可声明；
AGPL 不能混进非 AGPL 的项目；**无许可证的不能抄**（著作权默认归作者）。

翻译完有两步必须做，缺一步就会出现「导入成功但样式悄悄没了」：

1. 用稿台的清洗器**逐部件比对清洗前后丢了什么**；
2. 端到端渲染一篇样稿，确认没有残留占位符。

> 一条踩过的坑：样式值里的 `{{变量}}` 占位符曾经被清洗器连同整条声明一起丢掉，
> 样式包的部件**悄悄没了样式**而且不报错。所以「占位符还在不在」和
> 「颜色有没有真的上到渲染结果里」是两件事，两条都要验。

## 10. 配图

稿台**不生图**。图是你在别的地方生成的（生图工具、截图、照片），稿台负责把它收进本地素材库，
再让你把它插进正文——插进正文之后，复制排版正文、推草稿，那张图才会跟着走。

```
外部生图 → 上传进素材库 → 稿件页「插入图片」→ 正文里出现 ![配图](/api/files/img/…)
   → 推草稿时稿台逐张换成微信自己的地址 → 草稿箱里的图能正常显示
```

完整的接口、文件命名规则与 2000px 尺寸红线见 [`spec.md` §3.7](spec.md#37-素材库与插图)。

### 10.1 两个入口

| 入口 | 做什么 |
| --- | --- |
| 素材库页（`/files`）顶部的「上传图片」 | 批量把图存进来；每张图有「复制引用」「复制地址」 |
| 稿件页的「插入图片」 | 「从本机传图并插入」一步到位；或从素材库里点一张直接插进正文 |

图插在**正文编辑框的光标位置**（先把光标放到想插图的地方，再点「插入图片」选图）；
「插入图片」入口只在正文阶段出现。插完记得点「保存修改」。

没保存也能看效果：点「公众号预览」时，请求会带上编辑器里的当前正文，刚插的图会直接出现。

### 10.2 生成图解

正文阶段工具栏点「生成图解」，六种图型：

| 图型 | 适合的数据 |
| --- | --- |
| 条形排名 | 少类目高低比较 |
| 占比方块 | 构成比例（按 100 格分配） |
| 时间线 | 事件按时间推进 |
| 前后对比 | 两套方案 / 改前改后 |
| 步骤流程 | 操作步骤、管线 |
| 关键数字 | 2–6 个 KPI |

填标题与数据（输入框下方有格式提示），可选单位与来源；点「生成预览」后
本地 canvas 渲染成 2000px 宽的 PNG，点「插入到光标」落到正文。图会进素材库，
推草稿时自动上传成微信地址。

生成是本地渲染，不调模型、不花 token；数据缺了就由你补，不会替你编。

### 10.3 想要配图提示词

稿件页的「配图提示词」按钮会写一段**图像模型的提示词**——拿去别的生图工具用。
稿台只负责把它写好，不负责替你生。

### 11.1 资源与数据分离

严格分开两套目录：

- **只读资源**（`resources/`）：提示词、公开专题、技能卡。打包后位于 `resources/app-resources`，

- **可写数据**（用户数据目录）：`.env`、SQLite 库、本地专题、登录日志、本地配图。

## 12. 写自己的专题

在用户数据目录的 `data/local/topics/<你的专题 id>/` 下放两个文件：

```
meta.yaml     id / name / description / audience / tone / skills
rules.md      写作规则正文
```

`skills` 是可选的技能包 id 列表，写了之后这个专题在正文阶段会默认启用它们：

```yaml
skills:
  - human-writing
```

同 id 会覆盖内置专题。规则会被原样注入每一道工序的系统提示，所以写得越具体越有用
（「每段不超过 3 行」比「要专业」有用得多）。

### 13.1 占位符

模板里可以写占位符，稿台在发请求前一次性替换：

| 占位符 | 填进去的东西 |
| --- | --- |
| `{{topic}}` | 本次稿件所属专题的名字 |
| `{{topic_rules}}` | 专题规则原文 |
| `{{style}}` | 作者风格画像 |
| `{{brief}}` `{{angle}}` `{{outline}}` `{{article}}` | 前面已签字的阶段产出 |
| `{{length_target}}` | 本次的全文字数目标（见第 1 节） |
| `{{section_budget}}` | 每一节的字数预算（从已确认大纲的「篇幅」逐节取出来） |

`{{length_target}}` 会被替换成一段话，说明这次该写多少字、从哪来的。
稿台按「界面手填 → 用户输入里谈篇幅的那句 → 大纲的总字数估算 → 选题的适合篇幅 → 材料里写的
→ 默认 700–1200 字」这个顺序找这个数，六处都没有就用默认篇幅。
**删掉这个占位符不会让稿子写错，但字数就没有约束了。**

`{{section_budget}}` 只在正文阶段有值，写成一张逐节的账
（第 1 段多少字、第 2 段多少字）。只给一个全文总数，模型会把每一节都写短一点，
总数就凑不上；逐节给账才落得下去。大纲里没有「篇幅」时这一整块不出现。

这一块里还写着**结构锁**：正文的小节数必须和大纲的段落数一一对应
（大纲第 1 段写在正文开头不加小标题，从第 2 段起每段一个 `##` 小节），
不许在大纲之外另起小节，也不许把两段并进一个。
这一条不只是为了好看——服务端要靠它把正文的小节和大纲的段落对号，
对不上号才只能退回按平均份额补写，精度差一截。

## 14. 出包与本地环境

`desktop:build` 是一条链，每一步都是一道闸门：

```
next build
  → ensure-runtime-deps    补齐 standalone 里漏追踪的运行时依赖
  → copy-standalone-assets 补 public/ 与 .next/static，清掉 .env 与源码树
  → sanitize-standalone     白名单复核 + 断言产物里没有符号链接
  → prepare-resources       汇出只读资源到 dist/app-resources
  → electron-builder        出 NSIS 安装包与免安装版
```

其中 `ensure-runtime-deps` 是一道**必需**的闸门：Next 的 Turbopack 构建会漏掉 App Router 的
路由运行时（`next/dist/compiled/next-server/app-route-turbo.runtime.prod.js`）。
开发机上完全看不出来——Node 解析模块时会逐级向上找 `node_modules`，
standalone 上面还有项目根，项目根的 `node_modules/next` 是完整包，于是 require 成功；
但装到用户机器后没有这个兜底，结果是**页面正常、所有接口 500**。
这个脚本扫描产物里所有外部依赖，把包内解析不到的实体文件从项目 `node_modules` 补进产物。

### 打包时下载失败（网络受限环境）

electron-builder 需要从 GitHub 下载 NSIS / winCodeSign 等二进制，**它不读 git 的代理配置**，
shell 里默认也没有 `http_proxy`。直连 GitHub 不通时，前五步全部正常、只有最后一步卡死，
报 `Timeout awaiting 'request' for 600000ms`（实测 2026-10-26）。两条出路：

```bash
# 走本机代理（Clash 默认 7897）
HTTPS_PROXY=http://127.0.0.1:7897 HTTP_PROXY=http://127.0.0.1:7897 npm run desktop:build

# 或走 npm 镜像（代理也不通时）
ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/ npm run desktop:build
```

产物在 `release/`：

- `Gaotai-Setup-<version>.exe` —— NSIS 安装包，可自选安装目录
- `Gaotai <version>.exe` —— 免安装版

桌面版第一次运行会在用户数据目录里生成 `.env`（随机登录口令 + 会话密钥）。
**用户不需要输入它**：桌面客户端每次启动都会生成一个只存在于本次进程的「启动令牌」，
用它自动换一个会话（见第 15 节）。首启那次口令也会写进 `initial-password.txt`，
作为自动登录失败时的兜底，Electron 读走即删。

**浏览器直连时忘了口令怎么办**：桌面版口令由程序生成、用户通常从没见过它。
所以桌面版提供了一条找回路径——菜单「工具 → 显示本机口令」，或登录页上的「忘了口令？取回本机口令」按钮。
它走主进程读取本机 `.env`，不新增任何能被外部调用的 HTTP 接口。

**本机没有 Visual Studio 时**，装依赖要用 `--ignore-scripts`，再手动补原生模块与 Electron 运行时：

```bash
npm install --ignore-scripts
# canvas 的预编译二进制（版本一致时可直接从别处复制 build/Release）
node node_modules/electron/install.js
```

Electron 运行时下载走国内镜像：

```powershell
$env:ELECTRON_MIRROR='https://npmmirror.com/mirrors/electron/'
$env:ELECTRON_BUILDER_BINARIES_MIRROR='https://npmmirror.com/mirrors/electron-builder-binaries/'
```

出包前先关掉正在运行的实例（portable 目标会一直等文件锁），出包后清掉 `%TEMP%\ns*.tmp`。

## 15. 数据与安全的实现细节

### 15.1 打开就是用，不问你要密码

**普通用户不会看到任何登录界面**（授权激活页是另一回事，见 §16 授权）。

桌面客户端每次启动都会随机生成一个「启动令牌」，只通过环境变量交给后端（**不落盘、不进 `.env`**），
窗口打开前用它换一个会话。所以：

- 双击即用，没有口令框、没有「忘记密码」；
- 30 天的会话过期**对用户不可见**——每次启动都会自动续上；
- 万一还是落到登录页，页面也会自己用本机口令进去。

这条机制真正替掉的是「让人输口令」这个动作，而不是保护本身：
后端只监听 `127.0.0.1`，但**任何本地网页**都够得着这个端口
（CSRF / DNS rebinding）。没有会话，一个恶意网页能让你的浏览器替它调你的接口——
烧你的模型额度、推你的公众号草稿箱。

口令因此降级成**机器内部凭证**：

| 场景 | 要不要口令 |
| --- | --- |
| 桌面客户端（正常入口） | 不要。启动令牌自动换会话 |
| 浏览器直接访问 `127.0.0.1` | 要。本机口令存在用户数据目录的 `.env` 里 |

### 15.2 口令相关的实现细节

- 登录口令用 scrypt 加盐存储，校验走 `timingSafeEqual`。
- 会话是 HMAC 签名的紧凑令牌，服务端无状态，30 天过期。
- 模型 API Key 用 AES-256-GCM 加密后落盘，口令由 `.env` 的 `SESSION_SECRET` 派生。
- 公众号 AppID / AppSecret 只写进 `.env`，界面只显示掩码。
- 公众号封面凭证（永久素材 media_id）同样只写进 `.env`，界面不回显它。
- 登录失败会记审计日志（时间、来源、UA），连续失败过多直接拒绝。
- 密钥文件全部在用户数据目录，不进安装包，也不会随程序更新被覆盖。
- 后端子进程的输出落在用户数据目录的 `backend.log`（超过 2MB 自动清空重来）。
  桌面版没有终端，出问题时这个文件是唯一线索；启动期的致命错误还会另存 `startup-error.log`。

## 16. 授权（注册码激活）

稿台主体按 **AGPL-3.0-only** 发布（根 `LICENSE`），产品需激活后使用；激活不限制 AGPL-3.0
赋予的权利。Wechatsync 衍生组件保持 GPL-3.0-only（GPLv3），契约见 `docs/license-protocol.md`。

- **首次启动引导激活**：进入授权页（`src/app/license/`），输入 `GT-XXXX-XXXX-XXXX-XXXX` 注册码。
  注册码通过服务号或授权服务器领码页（`/redeem`）发放，一码一机。
- **激活后**：客户端调 `/v1/activate` 绑定本机机器指纹，换取 30 天有效签名令牌；令牌剩余不足 7 天
  自动调 `/v1/refresh` 续期，刷新失败不阻塞启动，进入 7 天宽限期。
- **未激活 / 令牌过期**：AI 功能（材料解读、选题、大纲、正文生成、获取新增或更新资产）不可用；
  本地受限模式保留本地编辑与排版，已缓存的技能包、提示词、排版模板仍可离线使用。
- **资源加密下发**：技能包、提示词、专题、排版包从安装包剥离，激活后经授权服务器
  `/v1/assets/:name` 加密下发并缓存到本机；资产密钥从令牌派生（HKDF-SHA256），不落盘。
- **开发旁路**：`GAOTAI_LICENSE_BYPASS=1` 时门禁放行，仅本地开发 / 测试用，打包脚本剔除该变量。
